## 1. Matcher: measured first, then fixed

Diagnosis on the home DB (55,792 FT records, 21,583 linked = 39%):

| Cause (all unmatched) | Share |
|---|---|
| Window miss: same-model+serial trim exists >60d before FT | 31.7% |
| Trim exists only AFTER the FT date (incl. pre-2013 FT era — trim data starts 2013-07) | 24.9% |
| Serial never appears under the model | 21.8% |
| Model name never trimmed (e.g. 8491-14, 8864, 1945302) | 19.1% |
| Bad FT metadata | 1.8% |
| In-window matcher logic gap | **0.8%** |

The cascade logic was nearly airtight — the losses were policy and coverage:

* **Save-time ordering hole.** Matching runs when the FT file is SAVED; an FT
  file processed in the same batch as (or before) its trim file matches
  nothing and stays NULL forever. Recent "misses" included 1–9 day gaps.
  Fix: `rematch_unlinked_final_tests()` — bulk, index-based (loads all trims
  once, bisect per FT record; seconds, not minutes) — runs automatically
  after every processing batch, BEFORE the drift advance. Existing links are
  never touched.
* **60-day window too tight for real WIP dwell.** Recent recoverable misses
  cluster at 63–176 days (trim → assembly → final test).
  `FINAL_TEST_MAX_DAYS_FROM_TRIM` 60 → 180, and the confidence decay beyond
  30d flattened 0.007→0.002/day so the scale spans the window (0.40 ≈ 180d;
  the old rate floored everything past ~73d at 0.40). Agreement/overkill
  queries still gate at ≥0.70, so distant links can't pollute them.
* **Glued-letter variants.** FT "7953-1" vs trim "7953-1A/-1B" (197 recent
  records): `_normalize_model` now strips trailing letters glued to a
  hyphenated numeric suffix. Numeric configs (8340-1) stay distinct.
* Not code-fixable, documented: models whose trim files were never ingested
  (8491-14: 842 recent FT records, 8864, 1945302 = likely customer P/N), and
  FT serials beyond any trim serial range (7458-1 serials 2927+, 8232-1,
  2511). If those trim folders exist at work, processing them will link
  retroactively — the post-batch rematch picks them up automatically.

## 2. FT watch: two new lot-watched TRIGGER metrics (10 → 12)

* **ft_fail_fraction** — per-FT-record fail flag clustered on FT `test_date`,
  lot value = fail fraction. Watches the last, most expensive station: "the
  latest lot is failing final test out of family." Dates < 2000 excluded
  (1899-12-30 epoch artifacts).
* **escape_fraction** — of FT records linked at confidence ≥ 0.5
  (`ESCAPE_MIN_CONFIDENCE`) to a trim the app ACCEPTED (PASS/WARNING), the
  fraction that FAILED final test. This is the signal neither station sees
  alone: the trim verdict losing its predictive power (assembly damage,
  station offset, margin erosion).

Both are MEAN-aggregated (fraction metrics), share the 0.02 σ floor, flow
through the same lot train/advance/requalify machinery, chart daily series on
the Model page focus chart, and appear in evidence exports automatically.
Bonferroni now divides by 12 via `len(WATCHED_METRICS)` — no code change.
Single source of truth: `drift_types.FRACTION_METRICS` (lots.py aliases it as
`MEAN_AGGREGATED_METRICS`). Models with no FT data train NOT TRAINED on these
two — honest, visible, harmless.

## Late-evening round: cold code review + live findings (same night)

James asked "you code reviewed all these changes tonight?" — a dedicated
cold-review pass (fresh reviewer, whole diff) then found what behavioral
verification hadn't:

* **BLOCKER — sibling-variant links.** The bulk rematch's variant index was
  keyed on the normalized family only, so FT "7953-1A" could link to a
  "7953-1B" trim — a match class `_find_matching_trim` never makes. Fixed:
  variant stage now requires one side to BE the base form; negative test
  added; home-DB links written by the buggy pass scrubbed and affected
  models retrained.

  changes under aggressive normalization) — FT "123" no longer links trim
  "123X".
* Late links vs the watch: rematch returns affected models; process page
  retrains them so newly linked old-dated records aren't stranded behind
  the escape/FT watermark.

  loaders and charts now use COALESCE(test_date, file_date).
* "Final Test Units" tab content was never packed (rendered empty) — packed.

  now anchored to the FT axis (short windows no longer land on empty charts;

**Answer: yes — measured on the work DB (last 2 years, conservative: raw
pre-trim worst point inside spec, no offset correction applied):**

* **12.6% of all trimmed units (2,923 of 23,129) already met linearity
  before the laser touched them.**
* Standouts: 8877-4 **84%**, 8167 **84%**, 8436 65%, 8755 59%, 8863 50%,
