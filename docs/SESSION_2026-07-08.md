# Session 2026-07-08 — Live-use fixes from James's first hands-on pass

Follow-ups from James using the app on real data. Each item is a user-reported
finding, its root cause, and the fix. All fixes are covered by the standing QA
sweeps and/or new tests.

## 1. Model page: window filter All → 365/90 didn't zoom the chart back in

**Report:** on 8340-1, selecting All then returning to 365/90 left the y-axis
zoomed out.
**Cause:** the ±3σ control band for 8340-1 (σ=1.26 on a metric whose data
spans ~0.1) dominated the y-window computation, so every window looked alike.
**Fix (focus_chart.py):** the band participates in the y-window only when
`(band_hi − band_lo) ≤ 6× data span`; otherwise the chart zooms to the data
and an amber note explains "±3σ control limits off-scale (…) — baseline spans
mixed history". Verified ylim now differs per window.

## 2. Dashboard sparklines meaningless ("no way to tell what these charts mean")

**Fix (mini_trend_chart.py):** each sparkline now carries: what the line is
("daily linearity yield (0–100%)"), first/last dates at the corners, and the
latest value marked and labeled.

## 3. Both sparklines annotated "100%" / FT panel spanning to 2026-12-18

**Report:** "this is the intended design? both are at 100%?"
**Investigation:** two separate things.
  * The trim panel's 100% was REAL — the last day of data genuinely graded
    100% — but the unlabeled annotation read as the window yield and
    contradicted the 90.x% headline. Annotation now says "last day 100%".
  * The FT panel's end date was a DATA ERROR: exactly one final-test record,
    from file `8074-sn4 blue-1_12-18-2026_9-55 AM.xls` (model 8074, SN 4),
    carries a file_date of 2026-12-18 — five months in the future, a
    mistyped date in the filename. It stretched the FT trend axis to Dec 2026
    and supplied its "last day" value.
**Fixes:**
  * `core/yield_stats.py` — compute_yield excludes rows with
    `file_date > now + 1 day` from counts and trend and returns a
    `future_dated` count. Regression test:
    `tests/test_dashboard.py::test_compute_yield_excludes_future_dated`.
  * `gui/v6/widgets/yield_panel.py` — panel discloses
    "⚠ N future-dated record(s) excluded (check filename dates)".
  * `core/processor.py` — ingest guard: a future-dated file gets a
    quality_issues entry ("future-dated file (…) — check the date in the
    filename") and lands as data_quality="suspect" instead of silently clean.
  * `scripts/app_qa_sweep.py` — the dashboard-vs-SQL check applies the same
    upper bound, and a new data-quality check WARNs with the per-table count
    of future-dated records (currently 1, in final_test_results).
**Left for James at work:** the source file's date can't be guessed — correct
the filename (or delete + reprocess the record) when the true test date is
known. The sweep WARN will clear when it's fixed.
